# 场景 10：多代理泳道视图（前端观测）

- **验证方式**：浏览器（playground + 泳道视图切换），非自动化 e2e
- **维度**：并行执行的前端观测正确性——泳道分组、实时思考流、恢复还原

## 目的

并行委派发生时，会话按 agentPath 拆成泳道（主 Agent + 每个子代理一条）。泳道视图顶部
以 tab 页选择当前查看的代理，一次只展示一条泳道的思考流/工具卡/结论；未手动选择时自动
跟随运行中的泳道，点击 tab 后固定。刷新后恢复态同样还原泳道。

## 触发

```
请你在同一轮里一次性并行委派三个任务（用三次 delegate_agent 调用，不要等前一个
完成再发下一个）：1. 委派 geo-agent 查上海当前天气；2. 委派 finance-agent 查
1 USD 兑 CHF 汇率；3. 委派 echo-agent 计算 17*23。全部结果回来后汇总转述。
```

发送后点击面板头部「泳道」按钮切换视图；运行中与刷新后分别检查。

## 预期

1. 三个子 run 同一秒创建、同时 running（真并行，max_parallel=3）
2. tab 页齐全：主 Agent + geo/finance/echo 四个 tab，一次只展示选中泳道；
   运行中的泳道 tab 带 ● 脉冲标识与步数，选中 tab 高亮
3. 未点击 tab 时视图自动跟随运行中的泳道；点击某 tab 后固定该泳道不跳转
4. 各泳道实时流出思考（如 echo 的逐步验算、geo 的上游重试思考）
5. 刷新页面后恢复态仍还原泳道 tab（依赖 EventLedger 的 agentPath 持久化修复）

## 已知边界

- 事件到达序在两子 run 间可能不交错（一方先流完），泳道内各自时序仍正确；
  并行的判据以 DB 存在期相交为准（见场景 02）。
