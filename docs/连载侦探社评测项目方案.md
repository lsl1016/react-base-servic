# 连载侦探社：长期记忆与多智能体评测项目方案

> 目标：用一个可玩、可评判、复杂度可控的文字破案连载项目，把基座的长期记忆（memory + reflection + graph_memory）
> 与多智能体（delegate_agent 并行委派）能力"压"到真实使用场景里，并且**每一轮玩法都同时是一次评测**——
> 答案在案件脚本（ground truth）手里，判分机械可查，不需要另建评测基建。

## 1. 项目定位

你是委托人，向"连载侦探社"接连环案件。每个案件（case）是一个自洽的破案 episode；
但凶手网络的 meta-plot 线索散落在各案之中，需要跨几十次会话、数天时间才能拼出全貌。

它同时是三样东西：

| 形态 | 说明 |
|---|---|
| 一个可玩的产品 | 文字冒险游戏，走基座 React 会话（web SDK 泳道视图 + 回放页） |
| 一套评测协议 | 跨案记忆命中率、矛盾计数、写入审计、并行收益，全部可机械判分 |
| 一份能力验收清单 | memory 分层、reflection 整理、delegate_agent 隔离、skill 触发，各得其所 |

## 2. 为什么这个题材"可以随便评判"

长期记忆和多智能体的失败，在 demo 里极难暴露，在评测集里又显得做作。破案题材让两者都有了**客观判据**：

1. **状态有 ground truth**。每案脚本是人工写定的：线索内容、NPC 证词、真相、时间线，全部白纸黑字。
   模型说错任何一句事实，对照脚本即可判定，不需要人工主观评价"记忆得好不好"。
2. **记忆失败 = 矛盾，一眼可见**。把死者性别搞错、让已退场 NPC 再次出场、重复询问已经问过的证人——
   这些是"记忆没跟上"的直接证据，读一遍回放就能数出来。
3. **知情边界天然存在**。三条调查线的证词互相独立，子侦探只能看自己那条线的材料。
   "引用了不该知道的证词"= 信息越权，同样是机械判据。
4. **单案复杂度低，跨案才见真章**。一案三线索五证人，任何模型都能"演好"一集；
   但第 8 案还要记得第 2 案的打火机牌子，只有长期记忆真的在工作才行。
5. **历史材料可以物理下架**。案卷服务只提供当前案件的材料（见 §5）——历史案的证词查不到了，
   这时问"第 3 案凶手留下的打火机什么牌子"，模型**只能**靠记忆回答。这是整个评测的支点：
   把"检索能力"从被测变量里剥离出去，剩下的就是纯记忆能力。

## 3. 玩法与案件结构

### 3.1 游戏循环

```
玩家（委托人）
   │  「侦探社，我妻子失踪了」
   ▼
主侦探（主 run，React 会话）
   │  读入本案件简报 → 规划三条调查线
   ├─ delegate_agent → 现场侦探（line=scene）    ┐
   ├─ delegate_agent → 走访侦探（line=people）   ├─ 并行子 run（max_parallel=3）
   └─ delegate_agent → 档案侦探（line=archive）  ┘
   │  汇总三线报告 → 交叉推理 → 指认凶手
   ▼
结案：memory_write 沉淀案件结论（detached）+ 关键事实（resident）
   │  （会话变长触发压缩后，reflection 自动整理记忆）
   ▼
下一案（隔天/隔周再玩）——meta-plot 暗线继续
```

### 3.2 三条调查线与子侦探

| agent_key | 调查线 | 工具（tools_json 白名单） | 典型任务 |
|---|---|---|---|
| `det-scene` | 现场勘验 | `case_scene` | 勘验现场、检验物证 |
| `det-people` | 人物走访 | `case_interview` | 询问 NPC、核实不在场证明 |
| `det-archive` | 档案检索 | `case_archive` | 查前科、查户籍档案、查历史案卷（限本案材料） |

三个子 Agent 在 `tblLlmAgent` 注册，各自 `tools_json` 只绑自己那条线的工具——**工具级硬隔离**，
子侦探想越线也调不到别的工具。主侦探拥有全部三个工具（可自己补查），但评测时统计它"抢活"的程度
（主 run 直接查证的比例）作为委派质量指标。

### 3.3 meta-plot 暗线

每案脚本携带 1～2 条暗线线索（如"凶手惯用左手"）。暗线不进任何一案的"真相推理必需集"——
不靠记忆也能破单案，但连破 N 案后最终章指认幕后主脑时，**必须**召回历史暗线。这是记忆评测的"大题"。

## 4. 案件脚本规范（ground truth）

一个案件一个 YAML，全项目所有判分都以它为准。放 `detective/cases/`，git 追踪。

```yaml
case_id: CASE-003
title: 打烊后的第三只茶杯
briefing: |                 # 开案简报，玩家第一轮会话注入
  周账房报告茶馆打烊后有人出入……

scene:                      # line=scene，case_scene 工具按 id 返回
  - id: S1
    title: 现场照片
    content: |
      茶桌上有三只杯子，其中一只杯柄朝右——死者是左撇子……
  - id: S2
    title: 烟灰缸
    content: |
      一枚登喜路牌烟蒂，丝质滤嘴有牙印……

npcs:                       # line=people，case_interview 按 name 返回证词
  - name: 陈掌柜
    testimony: |
      打烊后我只给周账房留过门……
  - name: 小翠
    testimony: |
      那晚我看见掌柜的在数钱，数错三次……

archive:                    # line=archive，case_archive 按 query 返回
  - id: A1
    title: 周账房户籍卡
    content: |
      男，四十一岁，右手执笔（档案记载）……   # 与 S1 矛盾，交叉验证点

truth:                      # 本案真相（判分基准，绝不注入给模型）
  culprit: 陈掌柜
  method: 伪证嫁祸
  key_evidence: [S1, 小翠]

meta_plot:                  # 暗线线索，跨案拼图用
  - hint_id: M3-1
    content: 真凶惯用左手，而周账房是右利手
    truth_link: MASTER      # 指向最终章幕后主脑设定

memory_quiz:                # 本案事实题（进跨案题库，历史案评测出题用）
  - q: 第三案中烟灰缸里的烟蒂是什么牌子？
    a: 登喜路
  - q: 第三案中谁为周账房作证留门？
    a: 陈掌柜
```

约束：

- `memory_quiz` 的答案**只允许**出现在本案材料里，且下一案开案后案卷服务不再提供本案材料（§5）；
- NPC 证词要设计"单线可信、交叉才见伪"的结构——这是逼模型真正汇总三线报告而不是偏听一线；
- 证词里的手机号/证件号**不要**用真实形态（见 §9 敏感拦截一节）。

## 5. 案卷服务（case server）

一个独立的微型 HTTP 服务（单文件 Go，约 200 行），职责只有三个：

1. 按 `case_id` 加载案件 YAML，按 `line` 参数返回对应调查线的材料片段；
2. **只暴露当前案件**——`GET /case/current` 返回活动案卷号，历史案卷一律 404。这是评测支点；
3. 记录访问日志（谁在什么时候查了什么），供 E4 越权审计交叉核对。

三个工具在 `tblLlmTool` 注册为 http 型工具，指向案卷服务：

| 工具名 | 入参 | 返回 |
|---|---|---|
| `case_scene` | `evidence_id` | 对应现场材料正文 |
| `case_interview` | `npc_name` | 该 NPC 证词全文 |
| `case_archive` | `query` | 关键词命中的档案条目 |

工具 `permission_mode` 用默认 `auto`（查证材料无风险）。结案后把 `current` 切到下一案，
旧案卷从服务可查范围中移除。

> 也可以把案卷服务做成本服务的一个 debug 控制器，但独立小服务更干净：评测对象是基座，
> 评测道具本身不应和被测系统耦合部署。

## 6. 基座能力映射

| 基座能力 | 在本项目中的角色 | 关键实现/配置 |
|---|---|---|
| React 引擎 | 主侦探推理循环 | 既有能力，零开发 |
| delegate_agent 并行委派 | 三线并行调查 | `tblLlmAgent` 三条定义 + `subagent.max_parallel: 3`，泳道视图观察 |
| 长期记忆 | 跨案案件结论与玩家偏好 | `memory.enabled: true`，分层策略见 §6.2 |
| reflection | 长会话压缩后自动沉淀遗漏事实 | `memory.reflection.enabled: true`，`source=reflection` 可审计 |
| graph_memory | 人物关系/时间线（"A 和 B 何时认识"） | 可选 M3 接入，`graph_memory.enabled` |
| Skills | 调查方法论沉淀 | `detective/skills/*.SKILL.md` 经 `/skill/import_zip` 导入 |
| 定时工作流（可选） | "晨报"：每天推送一封匿名信推进暗线 | 复用定时触发工作流方案 |
| 回放页 + 泳道视图 | 评测取证工具 | 既有能力，E2/E4 的证据来源 |

### 6.1 配置（conf/mount/custom.yaml，键名已核对）

```yaml
llm:
  react:
    memory:
      enabled: true
      resident_max_items: 16
      resident_budget_chars: 2000
      index_max_items: 64
      detached_max_items: 500
      allow_user_scope: true          # caller_user 维度：每个玩家自己的记忆空间
      reflection:
        enabled: true
        cooldown_minutes: 60          # 专门测 reflection 时临时调成 1
        max_writes_per_run: 20
        transcript_char_limit: 16000
    subagent:
      enabled: true
      max_parallel: 3
      max_depth: 2
    # M3 可选：
    # graph_memory:
    #   enabled: true
    #   endpoint: "http://127.0.0.1:8003"
    #   group_scope: caller_user
    #   inject: { enabled: true }
    #   write: { enabled: false }     # 灰度，默认关
```

### 6.2 记忆分层策略（本项目的使用约定）

| 内容 | 层 | 理由 |
|---|---|---|
| 案件结论（凶手、手法、关键证据 id） | detached，`tags=case,CASE-003` | 目录即可唤起，全文按需 `memory_read` |
| 极高频事实（玩家称呼、侦探社规矩、暗线已拼出的片段） | resident | 每轮必见，预算内 |
| 玩家偏好（"我喜欢硬核推理别给提示"） | caller_user 空间 | 用户级隔离 |
| 玩家钉死的事实（"我就是要怀疑周账房，别劝我"） | `tags=locked` | reflection 只读，防自动整理覆盖 |

写入纪律本身就是被测行为：主侦探该不该记、记成什么层、reason 写得是否诚实，都在 E3 审计范围里。

### 6.3 Skills（两条，验证触发链路）

- `交叉验证方法论`：触发词"证词矛盾/对不上"——指导先列矛盾点再指认；
- `时间线重建`：触发词"时间线/那晚几点"——指导按证人逐一排时刻表。
- 源文件放 `detective/skills/`（git 追踪），导入走 `/skill/import`。

## 7. 评测协议

### E1 跨案记忆命中率（主指标）

- 题库 = 各案 `memory_quiz` 累积 + 暗线拼图题；每结一案，出 K=5 道**历史案**题（与当前案无关）。
- 判分：答案与 ground truth 精确匹配/同义即对。先人工判，M3 起可用裁判模型半自动。
- 记录：命中率、答错题目的答案来源（对应记忆条目是否存在、在哪层）。
- 关键控制：出题前确认案卷服务已下架相关历史材料——确保答案只能来自记忆，不能来自工具。

### E2 矛盾计数（连续性）

每案游玩回放中统计：与历史事实冲突的陈述次数（性别/时间/人物关系错误、已退场 NPC 再出场、
重复询问已给出完整证词的证人）。人工读回放即可，量小（每案一局）。矛盾数是记忆失效的"事故率"口径。

### E3 写入质量审计（直接查库）

```sql
-- 每案结案后跑一遍
SELECT layer, tags, title, source, version, updated_at
FROM tblLlmMemoryItem WHERE state='active' ORDER BY updated_at DESC;

SELECT action, source, COUNT(*) FROM tblLlmMemoryRevision
GROUP BY action, source;
```

判定三类问题：**漏**（脚本里的关键事实没进记忆）、**脏**（记了错误/无关内容，如把玩家随口猜测记成事实）、
**冗余**（同指纹未收敛、应 update 却 create——正常应看到 `converged=true` 路径）。
reflection 的贡献单独看 `source=reflection` 的修订条目，对照被压缩对话判断"捞回来了没有"。

### E4 多智能体规约（泳道视图 + 回放 + 访问日志）

| 判据 | 合格线 | 证据 |
|---|---|---|
| 越权 | 子侦探引用了非本线证词 = 0 次 | 回放 + 案卷服务访问日志交叉 |
| 真并行 | 三线子 run 时间窗重叠 | 泳道视图截图 |
| 委派质量 | 主 run 亲自查证比例、派单描述是否说清任务 | 回放读 delegate_agent 入参 |
| 汇总质量 | 最终指认引用了三线各自至少一条证据 | 结案陈词对照 `truth.key_evidence` |

### E5 对照组矩阵（净贡献拆解）

同一案卷在不同配置下各跑一局（新玩家会话，控制顺序防位置效应）：

| 组 | memory | reflection | max_parallel | 度量 |
|---|---|---|---|---|
| A 全开 | on | on | 3 | 基准 |
| B 无记忆 | **off** | on | 3 | E1 命中率差 = 记忆净贡献 |
| C 无整理 | on | **off** | 3 | 长会话段的 E2/E3 差 = reflection 净贡献 |
| D 串行 | on | on | **1** | 破案耗时差 = 并行收益 |

### 评分表（每案一份，模板入 `detective/eval/scorecard.md`）

```
CASE-003  玩家: keke  配置组: A  日期: 2026-09-14
E1 命中率: 4/5（错题: M2-1 暗线，对应记忆条目 #47 不存在 → 漏记）
E2 矛盾: 1（把第二案死者职业说错）
E3 审计: 漏 1 / 脏 0 / 冗余 0；reflection 贡献 3 条 revision
E4 越权 0；并行重叠 6.2min；主 run 亲自查证 2 次
备注: reflection 在压缩后把小翠证词补记了（source=reflection）
```

## 9. 风险与注意点

1. **敏感拦截会拦案件内容**（重要）。`service/memory/memory.go` 的内置正则会拒绝身份证号、手机号、
   各类密钥形态。写案时证词里的证件号必须用非真实形态（如"户籍卡编号 沪-1993-0417"）。
   反过来，可以**故意**在某一案放一个真实形态的手机号——验证 `memory_write` 被拒后模型的行为
   （应改写脱敏而非放弃），这本身就是一次安全机制的正确性评测点。
2. **resident 预算挤兑**。默认 16 条/2000 字符。玩到 6 案以上，常驻层会满，预算截断逻辑
   （`renderMemoryContext` 的 truncated 提示）会被真实触发——这正是 E1 错题归因的素材，不要调大预算回避它。
3. **reflection 冷却**。60 分钟冷却意味着连玩两案不触发第二次整理。专门测 C 组时把
   `cooldown_minutes` 临时调成 1，并在测完改回。
4. **同案不可重玩**。重玩同一案，答案会从工具结果重新获得，E1 就废了。对照实验一律用新案卷新会话。
5. **案卷服务的"只暴露当前案"是纪律线**。它一旦漏了历史材料，整个记忆评测失效。给案卷服务加一条
   自测：启动时断言可查集合 == 当前案卷。
6. **拦截"睁眼说瞎话"**。模型可能在结案陈词里编造未查到的证据（幻觉）。E4 汇总质量一栏已含此判据：
   引用的证据 id 必须能在访问日志里找到对应的工具调用。

## 10. 附录：备选题材

- **AI 剧本杀主持人**：每个 NPC 只知道自己目击的事件，测记忆的"知情边界"，越权即判负。
  评测同样机械，但多智能体结构弱一些（NPC 之间无委派关系）。
- **长线陪练教练**：面试/错题陪练，记忆=弱点档案，隔 N 轮考历史错题，命中率即记忆分；
  多智能体=出题官/追问官/评估官并行。最朴素、评测最硬，但"新奇感"不足。

两者可作为连载侦探社 M1 之前的练手（一天内可跑通最小闭环），或作为评测矩阵的补充题源。
